# Parallel-Programming

Лабораторная работа № 2

Реализация умножения квадратных матриц двумя способами:

- **Последовательно** — классический тройной цикл (`multiplySequential`).
- **Параллельно** — с использованием OpenMP (`multiplyParallel`, `#pragma omp parallel for`).

Проект использует **модули C++23** (`import std;`, `export module ...`) и собирается через **CMake + MSVC**. В качестве генератора сборки можно использовать Visual Studio или Ninja.

Программа автоматически перебирает размеры матриц `200, 400, 800, 1200, 1600, 2000` и наборы количеств потоков `1, 2, 4, 8, 12`, ограничивая их доступным количеством логических процессоров.

## 📁 Структура проекта

```
.
├── Lab2/
│   ├── main.cpp
│   ├── matrix_core_n_files.cppm
│   ├── matrix_ops.cppm
│   ├── gen_mat.py
│   ├── check.py
│   ├── perf.py
│   ├── requirements.txt
│   └── CMakeLists.txt
├── .gitignore
└── README.md
```

Назначение файлов:

- `main.cpp` — точка входа, перебор размеров матриц и замеры времени.
- `matrix_core_n_files.cppm` — класс `Mat`, загрузка и сохранение матриц, запись результатов бенчмарков.
- `matrix_ops.cppm` — последовательное и параллельное умножение матриц.
- `gen_mat.py` — генерация входных матриц.
- `check.py` — проверка результатов с помощью NumPy.
- `perf.py` — построение графиков производительности.
- `requirements.txt` — зависимости Python.
- `CMakeLists.txt` — настройки сборки C++-проекта.

Файлы `matrix_*.txt`, `result_*.txt`, `benchmark.csv` и каталоги `build/`, `build-ninja/` не хранятся в репозитории. Они создаются при запуске программы и исключаются из Git с помощью `.gitignore`.

Графики PNG создаются скриптом `perf.py`. При необходимости их можно добавить в репозиторий как результаты экспериментов.

## 🚀 Сборка и запуск

Все команды ниже рассчитаны на Windows и PowerShell. После генерации матриц перейдите в каталог `Lab2` и выполняйте последующие команды из него.

### 1. Установить зависимости Python

Из корневой папки репозитория выполните:

```powershell
py -m pip install -r Lab2/requirements.txt
```

Или установите библиотеки вручную:

```powershell
py -m pip install numpy matplotlib
```

### 2. Сгенерировать входные матрицы

Перейдите в каталог `Lab2`:

```powershell
cd Lab2
```

Запустите генератор:

```powershell
py gen_mat.py
```

Скрипт создаст 12 файлов: по две матрицы для каждого размера от `200 × 200` до `2000 × 2000`.

Названия файлов:

```text
matrix_200_a.txt
matrix_200_b.txt
matrix_400_a.txt
matrix_400_b.txt
matrix_800_a.txt
matrix_800_b.txt
matrix_1200_a.txt
matrix_1200_b.txt
matrix_1600_a.txt
matrix_1600_b.txt
matrix_2000_a.txt
matrix_2000_b.txt
```

Генерация детерминирована: используется `seed = 20261011`. Поэтому при повторном запуске входные матрицы будут идентичными, что обеспечивает воспроизводимость экспериментов.

### 3. Собрать C++-проект

Находясь в каталоге `Lab2`, выполните следующие команды для сборки с помощью Visual Studio:

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

Если используется Visual Studio 2022, замените генератор на:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

**Альтернативный вариант — Ninja:**

```powershell
cmake -S . -B build-ninja -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-ninja
```

Для Visual Studio и Ninja используются разные каталоги сборки, чтобы избежать конфликта настроек генераторов.

Исполняемый файл будет находиться по одному из следующих путей:

```text
Visual Studio: Lab2/build/Release/Lab2.exe
Ninja:         Lab2/build-ninja/Lab2.exe
```

### 4. Запустить программу

Запускайте программу из каталога `Lab2`, чтобы она могла найти входные файлы `matrix_*.txt`:

**Для Visual Studio:**

```powershell
.\build\Release\Lab2.exe
```

**Для Ninja:**

```powershell
.\build-ninja\Lab2.exe
```

Пример вывода программы:


Значения времени приведены исключительно для примера. Реальные результаты зависят от процессора, количества потоков, компилятора и условий выполнения.

В результате работы создаются:

Общее время выполнения зависит от оборудования и может составлять от одной до нескольких минут.

### 5. Проверить результаты с помощью NumPy

Выполните команду из каталога `Lab2`:

```powershell
py check.py
```

Скрипт загружает исходные матрицы, вычисляет их произведение с помощью NumPy и сравнивает его с результатом C++.

Пример ожидаемого вывода:

```text
[OK] size=  200  max|diff|=0.000e+00
[OK] size=  400  max|diff|=0.000e+00
[OK] size=  800  max|diff|=0.000e+00
[OK] size= 1200  max|diff|=0.000e+00
[OK] size= 1600  max|diff|=0.000e+00
[OK] size= 2000  max|diff|=0.000e+00

RESULT: ALL OK
```

`max|diff|` обозначает максимальное абсолютное отличие между элементами проверяемых матриц. Если все проверки пройдены, скрипт выводит `RESULT: ALL OK`.

### 6. Построить графики производительности

Запустите:

```powershell
py perf.py
```

Скрипт создаст три графика:

- `time_vs_threads.png` — зависимость времени параллельного выполнения от количества потоков.
- `speedup_vs_threads.png` — зависимость ускорения от количества потоков с линией идеального ускорения.
- `speedup_heatmap.png` — тепловая карта ускорения в зависимости от размера матрицы и количества потоков.

Графики позволяют сравнить производительность последовательного и параллельного алгоритмов, оценить влияние количества потоков и проследить зависимость ускорения от размера задачи.

## 📊 Ожидаемые результаты

Ниже приведён пример результатов эксперимента. Фактические значения необходимо получать на используемом компьютере.

| Размер матрицы N | T_seq (мс) | T_par, 8 потоков (мс) | Ускорение, 8 потоков | Ускорение, 12 потоков |
|---:|---:|---:|---:|---:|
| 200 | ~9.5 | ~4.2 | ~2.24 | ~2.81 |
| 400 | ~72 | ~21.3 | ~3.40 | ~3.78 |
| 800 | ~653 | ~160.9 | ~4.06 | ~4.53 |
| 1200 | ~2778 | ~679.2 | ~4.09 | ~4.36 |
| 1600 | ~8810 | ~1885.0 | ~4.67 | ~3.62 |
| 2000 | ~22167 | ~4388.7 | ~5.05 | ~5.73 |

### Наблюдения

1. **Небольшие матрицы.** Для размеров 200 и 400 накладные расходы OpenMP заметнее относительно времени вычислений, поэтому использование большего количества потоков не всегда даёт существенное ускорение.

2. **Увеличение размера задачи.** При увеличении размера матриц растёт объём вычислений, а затраты на организацию параллельной работы становятся менее значительными относительно общего времени выполнения.

3. **Один поток.** Параллельная версия может работать немного медленнее последовательной. Это объясняется накладными расходами на организацию параллельной области OpenMP.

4. **Количество потоков.** Увеличение количества потоков не гарантирует пропорционального ускорения. На результат влияют количество физических ядер, аппаратная многопоточность, использование кэша и распределение вычислительной нагрузки.

5. **Размер матрицы 1600 × 1600.** В приведённом примере ускорение при переходе с 8 на 12 потоков снижается примерно с 4.67 до 3.62. Такое поведение может быть связано с особенностями оборудования и конкуренцией за вычислительные ресурсы.

## 📌 Вывод

В лабораторной работе реализованы последовательное и параллельное умножение квадратных матриц с использованием C++23 и OpenMP.

Производительность алгоритмов исследуется для разных размеров матриц и количества потоков. Корректность результатов проверяется с помощью NumPy, а результаты измерений сохраняются в CSV-файл и визуализируются графиками.

Эксперимент позволяет оценить ускорение параллельного алгоритма и показать, почему эффективность распараллеливания зависит от размера задачи и характеристик оборудования.
