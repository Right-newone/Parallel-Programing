# Лабораторная работа №3: Параллельное перемножение матриц с использованием MPI

Выполнил: Эльменкин Виктор
## 1. Цель работы
Изучение технологий параллельного программирования на примере библиотеки MPI. Реализация параллельного алгоритма перемножения квадратных матриц, замер времени выполнения, оценка ускорения и эффективности распараллеливания.

## 2. Описание реализации
В основе программы (файл `main.cpp`) лежит алгоритм блочного перемножения матриц. 
*   Матрица `B` целиком рассылается всем процессам с помощью коллективной операции `MPI_Bcast`.
*   Строки матрицы `A` равномерно распределяются между процессами с помощью `MPI_Scatterv`. Если размерность матрицы не делится нацело на число процессов, остаток распределяется по одной строке на первые процессы.
*   Каждый процесс вычисляет свою часть результирующей матрицы `C`, используя классический тройной цикл.
*   Результаты собираются на нулевом процессе с помощью `MPI_Gatherv` и записываются в файл `result.txt`.

Проверка корректности выполняется с помощью Python-скрипта `verify.py`, который сравнивает результат с эталонным, вычисленным с помощью библиотеки `NumPy`.

## 4. Анализ результатов

1. **Точность вычислений:** Максимальная разница (`Max diff`) во всех тестах равна `0.000e+00`. Это связано с тем, что исходные матрицы заполняются целыми числами от 0 до 9, и при перемножении таких матриц промежуточные результаты без потерь помещаются в тип `double`. Погрешность округления отсутствует, результаты полностью совпадают с эталоном `NumPy`.
2. **Ускорение (Speedup):** 
   * На малых размерах матриц (`N = 200`) время выполнения очень маленькое, поэтому накладные расходы MPI (на передачу данных и синхронизацию) превышают вычислительную нагрузку. В результате ускорение скачет, а на 4 процессах наблюдается даже замедление по сравнению с 2 процессами.
   * На больших размерах (`N = 2000`) ускорение достигает **3.16x** на 8 процессах. Время выполнения падает с ~5.7 секунд (1 процесс) до ~1.8 секунд (8 процессов).
3. **Эффективность (Efficiency):** С ростом числа процессов эффективность падает (до 40% на 8 процессах для `N=2000`). Это объясняется несколькими факторами:
   * **Коммуникационные издержки:** Пересылка больших объемов данных (матрицы B и частей матрицы A) отнимает значительное время. Локальная сеть или шина памяти не справляются с масштабированием.
   * **Ограничение по памяти:** Алгоритм требователен к пропускной способности оперативной памяти.
   * **Физические ядра:** Если на компьютере меньше 8 физических ядер, MS-MPI начинает запускать несколько процессов на одном ядре, что снижает реальный прирост производительности.

## 5. Вывод
В ходе лабораторной работы был реализован и протестирован параллельный алгоритм перемножения матриц с использованием интерфейса MPI. Эксперименты подтвердили работоспособность алгоритма и показали, что использование MPI позволяет существенно (до 3.16 раз) сократить время вычислений на больших задачах. При этом на малых задачах параллелизация неэффективна из-за накладных расходов на обмен сообщениями.
